# 개입 레이어 실제 환경 테스트 시나리오

실제 크롬·디스코드에서 guardian(판단 레이어)이 의도대로 동작하는지 확인하는 수동 테스트 기록.
자동 테스트로 확인할 수 없는 부분(크롬 확장, 배너, 탭 정리, 창 최소화, 디스코드 메시지)을 다룬다.

- 대상 단계: 4단계 `feat/guardian-executor` (실행기·크롬 확장)
- 명령어는 Windows **cmd** 기준 (`set`은 반드시 별도 줄로 입력)

---

## 1. 테스트 준비

### 1-1. 프로젝트 폴더로 이동

```cmd
cd /d "<프로젝트 폴더>"
```

- `<프로젝트 폴더>`는 이 레포를 클론한 본인 PC의 경로로 바꿔 입력한다 (예: `C:\projects\pattern-bridge`). 경로에 공백이 있으면 따옴표를 그대로 둔다.
- 이 문서의 다른 명령은 모두 프로젝트 폴더 안에서 실행한다.

### 1-2. 데모 DB 만들기 (처음 한 번만)

```cmd
npm run demo-db
```

- `data\pattern-bridge.sqlite`가 이미 있으면 멈춘다. `--force`를 붙이면 **기존 수집 데이터가 지워지니** 주의.
- 실제 데이터와 분리하고 싶으면 모든 터미널에서 `set DB_PATH=data\test.sqlite`를 먼저 입력한다.

### 1-3. collector, guardian 실행 (터미널 두 개)

```cmd
:: 터미널 1: collector
npm run dev
```

```cmd
:: 터미널 2: guardian (데모 모드)
set GUARDIAN_DEMO=1
npm run guardian:dev
```

- guardian 첫 줄에 `[guardian] started (demo=true, ...)`가 보이면 데모 모드가 켜진 것.
- 디스코드 메시지를 받으려면 OpenClaw가 실행 중이고 `.env`의 `OPENCLAW_*`, `NOTIFY_*`가 설정돼 있어야 한다.

### 1-4. 브라우저 확장 설치

크롬 계열 브라우저(Chrome, Edge, Whale, Brave 등)에서 쓸 수 있다. **쓰는 브라우저마다 따로 설치**하고 1-5의 토큰도 각각 입력한다.

1. 확장 관리 페이지 열기 → 개발자 모드 켜기
   - 크롬: `chrome://extensions`
   - 엣지: `edge://extensions` (개발자 모드는 왼쪽 메뉴 아래)
   - 웨일: `whale://extensions`
2. 기존 Pattern Bridge가 있으면 **삭제** (확장 ID가 고정되면서 바뀌었기 때문)
3. "압축해제된 확장 프로그램을 로드합니다"(엣지는 "압축을 푼 확장 로드") → `browser-extension` 폴더 선택
4. 권한(모든 사이트, 알림 등) 허용

### 1-5. 토큰 입력과 연결 확인

1. 프로젝트 폴더의 `.env`를 메모장으로 열고 `EXTENSION_TOKEN=` **뒤의 값만** 복사 (앞뒤 공백·따옴표 제외)

   ```cmd
   notepad .env
   ```

2. 브라우저 툴바의 퍼즐 아이콘 → Pattern Bridge 클릭(자주 쓰면 핀 고정) → 팝업 아래쪽 **연결 토큰** 칸에 붙여 넣고 **저장**
3. 확인
   - 토큰 칸 아래에 **토큰 저장됨**(초록색)
   - 팝업 "개입 일시 정지" 아래에 **개입 동작 중**(초록색). guardian이 꺼져 있으면 연결 안 됨으로 나온다
   - guardian 로그: `[extension-link] chrome extension connected` (엣지는 `edge ...`)
   - 탭을 바꾸면 collector 로그: `[browser-monitor] chrome activated tab=... <카테고리> <URL>`
4. 토큰이 없거나 틀리면 탭 정보가 저장되지 않는다. 이때 로그에 원인이 찍힌다
   - collector: `[browser-monitor] rejected report ...: bad token` → 토큰을 다시 입력
   - `origin not allowed` → 예전 확장이 남아 있음. 삭제 후 다시 로드

### 1-6. 코드가 바뀐 뒤 다시 테스트할 때

수정 커밋을 받은 뒤에는 아래를 다시 해야 새 코드가 반영된다. 토큰은 다시 입력하지 않아도 된다.

1. 최신 코드 받기

   ```cmd
   git pull
   ```

2. 확장 관리 페이지(`chrome://extensions` 등)에서 Pattern Bridge 카드의 **새로고침(↻)**. 여러 브라우저에 설치했다면 각각
3. collector, guardian 창에서 각각 **Ctrl+C**로 끄고 1-3의 명령으로 다시 실행
4. 1-5의 3번 항목으로 연결 확인

## 2. 데모 값

| 항목 | 실제 값 | 데모 값 |
| --- | --- | --- |
| R1 오락 연속 (낮 / 심야) | 40분 / 20분 | 2분 / 2분 |
| R1 유예 | 5분 | 30초 |
| R1 다시 열었을 때 (기간 / 유예) | 10분 / 1분 | 3분 / 10초 |
| R2 유예 | 5분 | 30초 |
| R2 확인 시각 | 매시 정각 | 정각 + `guardian:trigger`로 수동 실행 |
| R3 소비 과다 (기준 / 반복) | 2시간 / 30분 | 5분 / 3분 |

값은 `config/intervention.json`의 `demo.overrides`에 있다.

## 3. 시나리오

결과 칸은 테스트할 때마다 채운다.

### A. R1 오락 연속 → 오락 탭 정리

- **목적**: 오락을 연속으로 오래 보면 유예 후 오락 탭이 닫히는지
- **사전 조건**: 1장 준비 완료, 크롬에 쇼츠 탭과 오락이 아닌 탭(예: 노션) 하나씩
- **절차**
  1. 유튜브 쇼츠를 크롬 맨 앞에 두고 2~3분 계속 본다
  2. 배너가 뜨면 그대로 30초 기다린다
- **기대 결과**
  - 다음 분 판정 때 쇼츠 화면 오른쪽 위에 배너 (30초 카운트다운, "지금 닫기" 버튼)
  - 디스코드에 정리 예고 메시지
  - 30초 뒤 **오락 탭만** 닫힘 (노션 탭은 그대로)
- **확인할 로그 (guardian)**
  - `[guardian] now=entertainment/shortform streak=2m ...`
  - `[intervention] #N R1 decided, grace 30s`
  - `[messenger] #N R1: sent`
  - `[intervention] #N R1 executed by fallback` (5단계 전까지는 항상 fallback)

### B. R1 유예 중 이탈 → 일시 정지 → 복귀 시 이어서

- **목적**: 유예 중 오락에서 벗어나면 멈추고, 마감 전에 돌아오면 남은 시간부터 이어지는지
- **절차**
  1. A처럼 배너를 띄운다
  2. 카운트다운 중에 노션(또는 강의) 탭으로 이동, 10~20초 머문다
  3. 다시 쇼츠 탭으로 돌아온다
- **기대 결과**
  - 이동하면 5초 안에 배너가 사라짐
  - 돌아오면 배너가 **남은 시간**으로 다시 뜨고, 끝나면 오락 탭이 닫힘
  - 원래 마감 시각까지 돌아오지 않으면 개입이 취소됨
- **확인할 로그**: `R1 paused (user left entertainment)` → `R1 resumed` → `executed`, 또는 `cancelled: user_left`

### E. 팝업 개입 일시 정지 / 다시 켜기

- **목적**: 정지하면 개입이 멈추고, 진행 중이던 개입도 취소되는지
- **절차**
  1. A처럼 배너가 뜬 상태에서 팝업 → 30분 → **정지**
  2. 쇼츠를 2~3분 더 본다
  3. 팝업 → **다시 켜기**
- **기대 결과**
  - 정지하면 배너가 사라지고 탭이 닫히지 않음, 팝업에 "일시 정지 중 (시각)"
  - 정지 중에는 새 개입이 없음
  - 다시 켜면 팝업이 "개입 동작 중", 이후 조건이 되면 다시 개입
- **확인할 로그**: `[pause] paused by extension ...`, `R1 cancelled: guardian_paused`, `[pause] resumed by extension`

### F. R2 생산 모드 (수동 실행)

- **목적**: 생산 모드가 순서대로 동작하는지 (오락 탭 정리 → 전체 최소화 → 문서·사이트 열기)
- **사전 조건**: 저장하지 않은 작업은 저장해 둘 것 (창이 전부 최소화됨)
- **절차**
  1. 쇼츠 탭을 크롬 맨 앞에 둔다
  2. 새 cmd 창에서 실행

     ```cmd
     set GUARDIAN_DEMO=1
     npm run guardian:trigger -- R2 --force
     ```

  3. 다음 분 판정 때 배너가 뜨면 오락 탭에 머문 채로 30초 기다린다
- **기대 결과**
  - 현재 탭에 배너 "오늘 공부·작업 시간이 평소보다 부족해요…" + 디스코드 예고
  - 30초 뒤: 오락 탭 닫힘 → 모든 창 최소화 → (최근 7일 저장한 문서가 있으면 열림) → 생산 사이트가 열리고 크롬 창이 앞으로
  - 생산 사이트: 데모 데이터에서 같은 요일 유형·시간대에 많이 쓴 생산 도메인, 없으면 e-캠퍼스·노션
  - 유예 중 생산 탭이나 VS Code로 넘어가면 R2가 취소되는 것도 정상
- **확인할 로그**: `R2 decided, grace 30s` → `R2 executed by fallback`

### I. 크롬 계열 브라우저 두 개 동시 사용

- **목적**: 앞에 있는 브라우저의 탭으로 판정하고, 정리할 때는 모든 브라우저의 오락 탭을 닫는지
- **사전 조건**: 크롬과 엣지 모두 확장 설치 + 토큰 입력 (guardian 로그에 `chrome extension connected`, `edge extension connected`)
- **절차**
  1. 크롬에 쇼츠, 엣지에 강의(또는 노션) 탭을 띄운다
  2. 엣지를 앞에 두고 1~2분 → 크롬을 앞에 두고 쇼츠를 2~3분
  3. 배너가 뜨기 전에 엣지에도 인스타그램 같은 오락 탭을 하나 열어 둔다
- **기대 결과**
  - 엣지가 앞일 때 guardian 로그 `now=productive/...`, 크롬이 앞일 때 `now=entertainment/shortform`
  - R1 배너가 두 브라우저의 오락 탭에 뜨고, 실행되면 **양쪽 오락 탭이 모두** 닫힘 (강의 탭은 그대로)
- **확인할 로그**: collector `[browser-monitor] edge ...` / `chrome ...`, `R1 executed by fallback`

## 4. 주의 사항

- **판정은 1분 단위**: 매분 정각 + 3초에 직전 1분을 판정하므로, 조건을 채운 뒤 배너까지 최대 1~2분 걸린다.
- **1분 판정 = 가장 오래 앞에 있던 활동**: 로그를 보느라 cmd 창을 오래 앞에 두면 그 1분은 생산(work)으로 잡힌다. 시나리오 중에는 크롬을 앞에 둘 것. cmd를 10분 넘게 연속으로 보면 오락 연속 시간이 초기화된다.
- **디스코드 메시지 한도**: 분당 1회. 같은 분에 개입이 겹치면 뒤의 메시지는 보내지 않는다 (`[messenger] ... minute_cap`).
- **판정은 앞에 있는 창 하나 기준**: 창 두 개를 나란히 띄우면 마지막으로 클릭한 창만 본다. 한 창에 탭이 여러 개면 보고 있는 탭 하나만 본다.
- **확장이 연결돼 있지 않으면** 배너 없이 개입이 실행 실패로 취소된다 (`cancelled: execution_failed`). 팝업 연결 상태부터 확인.
- 모든 개입은 DB의 `interventions` 테이블에 상태·실행 주체·결과와 함께 남는다.
